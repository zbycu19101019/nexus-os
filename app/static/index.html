Szybki start

  • Zaloguj sie uzytkownikiem i haslem. Rola admin moze edytowac oraz wykonywac akcje systemowe.
  • Klodka w prawym dolnym rogu blokuje edycje zakladki. Admin moze ja otworzyc.
  • Przycisk KAFELKI pozwala adminowi zmieniac rozmiary sekcji i zapisuje uklad w przegladarce.
  • Okno TRANSFER CORE pokazuje wysylanie i pobieranie plikow oraz pozwala pauzowac, wznawiac i anulowac transfery.

Zasady bezpieczenstwa

  • Nie zapisuj hasel, tokenow API ani kluczy prywatnych w README, czacie, newsach lub publicznych udostepnieniach.
  • Terminal i Admin dzialaja z uprawnieniami serwera, wiec kazda komenda powinna byc sprawdzona przed uruchomieniem.
  • Przed zmianami VM rob snapshot. Przed zmianami calego panelu rob backup strony.
  • Publiczne linki Secure Drop traktuj jak jawne linki do pobrania.

Zakladki glowne

  • DASH: telemetria VPS, czas serwera, aktywna VM, ostatnie wiadomosci i stan panelu.
  • AI: komunikacja z asystentem Gemini przez backend panelu.
  • NEWS: zrodla RSS, miks wiadomosci, tryby alertow i obsluga materialow wideo gdy feed je dostarcza.
  • PLIKI: eksplorator serwera, edycja tekstowa, upload, download i smart-drop.
  • TERM: web terminal do komend serwerowych.
  • PROC: lista procesow, sortowanie, filtrowanie i zabijanie procesu.

Moduly operacyjne

  • VM: lista maszyn, start, stop, reboot, delete, edycja RAM/vCPU, logi, snapshoty, port forwarding.
  • HYPER-DECK: noVNC, kontrola podgladu, mysz, mute, Ctrl+Alt+Del i clipboard do VM.
  • Driver Vault: rozpakowane paczki sterownikow, kategoryzacja i wybor kategorii do podpiecia przy VM.
  • OS Forge: katalog ISO, pobieranie systemow i tworzenie maszyn gotowych do instalacji.
  • Pogoda: wpisujesz miasto lub kraj, panel pobiera aktualna i 72h telemetrie pogodowa.

Media i wspolpraca

  • Media Deck: prywatne audio/wideo z katalogu mediow na serwerze.
  • Cyber BBS: tablica postow, watki, komentarze, obrazy i reputacja.
  • Visual Archive: galeria obrazow z lightboxem i metadanymi.
  • Kanban: karty drag and drop dla pomyslow, zadan i list.
  • Secure Drop: generowanie linkow do plikow i statystyki pobran.
  • Object Storage: MinIO/S3, buckety ISO/media/backup/upload, presigned URL i Token Vault.

Technologia

Frontend
HTML/CSS/JS, single-page panel, localStorage dla sesji i ukladu kafelkow.
Backend
Python FastAPI, endpointy REST, WebSocket dla VNC/P2P/presence.
Proxy
Nginx jako publiczny reverse proxy z limitem uploadu ustawionym pod duze pliki.
Service
systemd: usluga nexus uruchamia backend panelu.
Object Storage
MinIO na 127.0.0.1:9000; FastAPI generuje presigned URL, a pliki ida do bucketow bez przepychania przez backend.
VM
KVM/QEMU/libvirt, virsh, noVNC i most WebSocket do konsoli graficznej.

Upload i routing plikow

  • Przeciagniety plik nie powinien otwierac sie w karcie, tylko trafic do Smart Drop.
  • ISO trafia do katalogu ISO, audio/wideo do mediow, obrazy do galerii, reszta do uploads lub aktualnego katalogu.
  • Po uploadzie panel sprawdza, czy plik faktycznie znalazl sie w miejscu docelowym.
  • Duze pliki moga isc przez Object Storage: panel pobiera podpisany URL i wysyla plik bezposrednio do MinIO.
  • Blad 413 oznacza limit proxy, serwera lub zewnetrznej warstwy przed Nginx; MinIO omija FastAPI, ale nadal przechodzi przez publiczna brame HTTP.

Backupy

  • Backup strony zabezpiecza kod i dane panelu NEXUS.
  • Backup calego serwera tworzy archiwum systemowe z pominieciem katalogow runtime typu /proc, /sys, /dev, /run i /tmp.
  • Przywracanie backupu strony wykonuj po upewnieniu sie, ze wybrany punkt jest poprawny.

VM checklist

  • ISO musi byc czytelne dla libvirt/qemu. Najbezpieczniej trzymac ISO poza prywatnym katalogiem /root albo nadac poprawne ACL.
  • Dla Windows podpina sie virtio-win lub wybrane kategorie sterownikow z Driver Vault.
  • Po starcie VM sprawdz status, logi libvirt i konsole noVNC.
  • Przed testami sterownikow lub sieci rob snapshot, zeby mozna bylo szybko wrocic.

Diagnostyka

  • Gdy akcja nie daje efektu, patrz na powiadomienie NEXUS i logi zakladki VM/Admin.
  • Gdy upload stoi, sprawdz TRANSFER CORE oraz miejsce na dysku.
  • Gdy VM nie startuje, otworz LOGI przy VM i sprawdz uprawnienia ISO, RAM/vCPU oraz sciezke dysku.
  • Gdy panel nie odpowiada, sprawdz usluge nexus, nginx i ostatnie wpisy logow systemowych.
